# PDFQFZ UI 规范文档

> 本文件是 PDFQFZ（WPF）界面开发的**唯一样式依据**。所有样式资源集中在 `PDFQFZ.WPF\Themes\Styles.xaml`。
> 规则：**做任何新控件前，先在本文档搜索有没有同类**——有就复用对应 Style 资源，没有就新增样式并**同时**补进本文件与 Styles.xaml。
>
> 版本：2026-09-10 规范落地（V38~V41 实装验证后固化）；2026-09-10 补充（V44~V46）：输入框/下拉框显式高度 30、输入框内边距 8,2、拖动条"方框适应内容"规范（§4.2/§4.3/§4.11）。

---

## 0. 使用总则（硬性）

1. **颜色一律用令牌**（`Color.*`），禁止在 XAML 中硬编码 `#RRGGBB`（极少数语义性 hover 深浅色除外，如 `#F0F0F0`/`#E0E0E0`，且须与本文件记录一致）。
2. **字体一律 `{StaticResource Font.App}`**，禁止硬编码字体名；窗口根元素统一 `FontFamily="Font.App"`。
3. **字号只允许下列档位（5 档）**：12.5（**默认**：正文、按钮、输入框、下拉、提示、日志）/ 13（SectionTitle 区块标题）/ 14（帮助窗口节标题）/ 18（帮助窗口大标题）/ 22（预览占位文字）。~~11 / 11.5 / 12~~ 已全部收敛到 12.5，禁止再出现。
4. **标题不要手写 `FontWeight="Bold"`**，用 `SectionTitle` 样式（13px 粗体）。
5. **按钮统一 `Button.Base` 派生**（Secondary/Primary/Danger/Square），圆角 6（方形入口除外）、MinHeight 30、Padding 12,5、Cursor Hand。
6. **下拉/菜单统一用全局 ComboBox / ContextMenu 样式**，禁止自绘覆盖控件；新增菜单项必须先查 MenuItem 模板（`ContentSource="Header"` 是必须项，禁用置灰绑定见 §4.4）。
7. **控件初始状态必须在 XAML 声明**：默认文字、默认勾选、默认可用性写进 XAML（如 `Content="盖章渲染"`、勾选框未选中时按钮 `IsEnabled="False"`），代码只负责按配置覆盖；禁止依赖某段代码初始化时才赋值（否则初始化路径未走到时控件为空/状态错，历史教训：盖章渲染按钮 `Content=""` 启动为空、未勾选时按钮未置灰）。
8. **新控件优先复用已有样式**：做新控件先搜索本文档与 Styles.xaml；确无同类才新增，且两处同步登记。
9. **交互状态记忆（展开/收起、上次使用值等）不属于设计规范**：由配置文件保存，新用户默认值按产品口径定（如按文字盖章默认收起），不写入本文档样式规则。

## 4. 控件规范

### 4.1 按钮
| 样式 | 场景 | 底/字/边 | 悬停 | 按下 | 禁用 |
| --- | --- | --- | --- | --- | --- |
| `Button.Base` | 基础（一般不用，仅派生） | 白底 / 黑字 / 深灰边 | 浅蓝底 `#F0F7FF` + 边框 `#4096FF` | 内容下移 1px（Padding `0,1,0,0`）+ Opacity 0.9 | Opacity 0.45 |
| `Button.Secondary` | 次要操作（方案1~4、恢复默认、使用说明、按文字放置印章、撤销放置等） | 白底 / 蓝字 / 蓝边 | 同 Base（浅蓝底+亮蓝边） | 同 Base | 0.45 |
| `Button.Primary` | 主要操作（蓝底白字，粗体 600） | 蓝底 / 白字 / 蓝边 | 同 Base | 同 Base | 0.45 |
| `Button.Danger` | 危险主操作（盖章并生成文件） | 红底 / 白字 / 红边，粗体 600 | 底与边变浅红 `#F06A6E` | 同 Base（下移+变深） | 0.45 |
| `Button.SecondarySquare` | **方形入口按钮**：勾选框+打开设置弹窗的组合入口（盖章渲染） | 白底 / 蓝字 / 蓝边，**CornerRadius=0 无圆角** | 浅蓝底+亮蓝边 | 同 Base | 0.45（**勾选框未选中 → 按钮整体置灰 IsEnabled=false，初始状态必须在 XAML 声明**，如 `IsEnabled="False"`；勾选后变亮可点） |
| `FoldButton` | 折叠/展开设置按钮（浅灰轻按钮） | 浅灰底 / 灰字 / 浅灰边，字号 12.5 | 底 `#E0E0E0`、字变深 | 底 `#D0D0D0` | — |
| `HistoryDeleteButton` | 历史下拉删除叉（✕） | 透明 / 灰字 ✕ 20×20，字号 12.5 | 底 `#FFF1F0`、叉变红 | — | — |

通用几何：圆角 6（方形入口 0）、`MinHeight=30`、`Padding=12,5`、`Cursor=Hand`。
**按压反馈（所有圆角/方形按钮统一）**：按下时内容下移 1px 产生按压感 + 整体 Opacity 0.9。实现：模板内 `Border.Padding` 从 0 变为 `0,1,0,0`（禁止用 RenderTransform 位移——WPF 模板内命名 Transform 的 Trigger 不可靠，历史教训）。
**宽度约定**：文字类按钮宽度 = 内容 + 左右 Padding（12×2）后留余量；固定宽按钮须验证文字完整显示（历史教训：56 宽"方案1"被裁，改 72）。

### 4.2 输入框 TextBox / PasswordBox
- 全局样式：白底、深灰边 1px、圆角 6、`Padding=8,2`、`Height=30`、内容垂直居中。
- **`Padding=8,2` 是硬性值（上下内边距 2px）**：12.5px 中文字体行高约 19px，30 高内内容区 = 30−4−2 = 24px，文字完整显示。曾用 `Padding=8,5` 导致内容区仅 18px、文字被裁剪一半（V46 修复）。
- **显式 `Height=30`，禁止仅 `MinHeight=30`**：MinHeight 会被内容撑破（内容 31px 时实际渲染 31px，比下拉框 30px 高 1px，用户目测不一致；V45 修复）。
- 聚焦：边框变主色蓝、加粗 1.5px。禁用：底 `#E8E8E8`、字 `#999999`。
- **禁止**在具体窗口覆盖模板或改背景。
- **高度统一 30（显式 `Height=30`）**：所有输入框、下拉框、密码框、预览工具栏按钮/页码框统一（含弹窗内输入框）。

### 4.3 下拉框 ComboBox
- 全局样式：白底、深灰边 1px、圆角 6、`MinHeight=30`、`MinWidth=80`。
- 悬停边框变蓝；下拉弹出层：白底、圆角 6、`MaxHeight=220` 滚动、`VerticalOffset=2`、淡入动画。
- 下拉项（ComboBoxItem）：圆角 4、`Margin=2,1`、`Padding=8,5`；hover/选中 = 浅蓝底 `#E6F0FF`；选中另加蓝字 + 字重 600。
- 可编辑模式（按文字盖章输入等）：隐藏选中项、显示内嵌文本框，样式与输入框一致。
- **宽度约定**：下拉框宽度与同排输入框对齐；内容放不下时加宽而不是截断（历史教训）。
- **印章文件 / 当前文件下拉框显式 `Height=30`**，与输入框绝对一致；**禁止 `MaxHeight`**（只限上限、不保最小，内容少时框会缩矮，历史教训）；可编辑模式下内嵌文本框样式与输入框一致。

### 4.4 菜单 ContextMenu / MenuItem（方案按钮、右键菜单等）
- ContextMenu：白底、深灰边 1px、圆角 6、`Padding=4`。
- MenuItem：圆角 4、`Margin=2,1`、`Padding=8,5`、字号 12.5；hover = 浅蓝底；禁用 = 灰字（`Color.TextHint`）。
- **模板必须 `ContentSource="Header"`**（漏写会导致菜单项空白、菜单缩成极小，历史教训）。
- **禁用置灰颜色绑定**：模板中 `ContentPresenter` 必须写
  `TextElement.Foreground="{Binding Foreground, RelativeSource={RelativeSource TemplatedParent}}"`
  ——**禁止用 `TemplateBinding` 绑定附加属性**（TemplateBinding 不支持附加属性，绑定静默失效，历史教训：加载方案置灰不生效）。
- 菜单项"未保存→加载置灰"等状态用 `IsEnabled` 控制，禁止手工改文字颜色。

### 4.5 勾选 CheckBox（方形勾选规范）
- **方形勾选框：不带圆角**（与圆角操作按钮区分）；方框 16×16、白底。
- 未选中：灰边 `#C6CAD2`；**选中：蓝底 `#1677FF` + 白勾**（Path 对勾，圆头端点）；hover：边框亮蓝 `#4096FF`；禁用：整体 Opacity 0.45。
- 字号 12.5、`Cursor=Hand`、内容垂直居中、文字与方框间距 8。
- **方形入口组合**（盖章渲染）：方形勾选框 + `Button.SecondarySquare` 方形按钮；未勾选时按钮整体置灰（IsEnabled=false）不可点，勾选后变亮可点、点击弹设置窗。
- RadioButton 沿用系统模板，仅字号 12.5。

### 4.6 标题与提示文字
| 样式 | 用途 | 规格 |
| --- | --- | --- |
| `SectionTitle` | 区块标题（"源文件""盖章方式""印泥浓淡不均"等） | 13px 粗体、`Color.Text` |
| `SectionHint` | 区块右上角提示（"选择盖章方式与输出效果"等） | 12.5px、`Color.TextHint` |
| `LogText` | 操作提示区/日志文字 | 12.5px、`Color.TextSecondary`、Wrap、行高 20 |

### 4.7 分区卡片 Card
- 白底、边框 `#C6CAD2`（比全局边框深，保证分区边界清晰）、圆角 10、`Padding=14,12`。
- 主界面 1~5 区块统一：`Style="{StaticResource Card}"` + 区块间距 `Margin="0,0,0,12"`。
- **弹窗内功能块同样用 Card 分块**（如盖章渲染参数窗：明暗与纹理/斑点/颜色 3 块），块间距 `Margin="0,0,0,12"`。

### 4.8 折叠区（展开/收起设置）
- 箭头提示：`FoldTip`（12.5px、`Color.TextHint`、Cursor Hand）。
- 展开/收起按钮：`FoldButton`（见 4.1）。
- **收起态高度规范**：收起时标题行（序号+标题+提示+折叠按钮）底部间距归零（`Margin=0`），标题行在卡片内**上下居中**（Card Padding 12/12），收起态高度紧凑（约标题行高 + Padding 24）；展开时标题行底部间距恢复 10（与内容分隔）。由折叠逻辑统一设置标题行 Grid 的 Margin（收起 0 / 展开 `0,0,0,10`）。
- 展开内容左缩进 34px（`Margin="34,0,0,0"`，与折叠箭头对齐），内容行间距 8。
- 展开后若内容超出可视区，自动滚动到展开区域底部；底部虚化提示不遮挡内容。

### 4.9 视图切换 Toggle.ViewMode（单页/双页/放大）
- 未选中：与 Button.Secondary 同风格；选中：浅蓝底 `#E6F0FF` + 蓝边框加粗 2px + 深蓝 `#0958D9` 粗体字；未选中悬停：边框变蓝、底 `#F5F9FF`。

### 4.10 滚动条（全局）
- 宽 10、透明轨道、圆角滑块 `#B8BEC9`（悬停 `#9AA1AD`）；点击轨道直接定位由各窗口 `ScrollViewer_TrackJump` 事件统一处理；滑块行内数值框可手动输入（输入后自动生效并移动滑块，超范围跳到最贴近值）。

### 4.11 标题-内容组合区块（Card 容器，通用容器规范）
- **用途**：一切"标签 + 内容"分区的容器。未来标题下面是滑块行、按钮行、下拉行、复选框行，容器都统一套本规范。
- **结构**：一个边框区块（Border），内部 = 标签区 + 内容区。
- **默认上下布局**：标签在上、内容在下（如拖动条：标题上、滑块行下）。
- **变体左右布局**：标签在左、内容在右（未来需要时启用，内容垂直居中）。
- **标签**：`SectionTitle`（13px 粗体），显示必须用 XAML Binding（如 `Text="{Binding Title, RelativeSource={RelativeSource AncestorType=UserControl}}"`），禁止依赖 DP 回调赋值（§0.7）。
- **方框适应内容**：先定内容尺寸，留边距后让方框自然包裹；禁止先画死方框再塞内容（历史教训：拖动条 V45）。
- **内边距/间距**：区块内边距与内容区-标签间距按 §5 统一值；上下布局时标签与内容间距 6~10，左右布局时标签右间距 8。
### 4.12 拖动条控件 NumericSliderRow（可复用内容控件，`Controls\NumericSliderRow.xaml`）
- **用途**：数值参数行的标准内容组合 = **滑块 + 数值框 + 上下箭头**一体；容器用 §4.11（标题上、滑块行下，两行一框：浅灰底 `#F7F8FA`、细边 `#E5E6EB`、圆角 6、`Padding=8,6`）。
- **布局原则：内容一体，方框适应内容**——先定内容尺寸（滑块 24 高、数值框 58×24、箭头按钮 18×13×2），留边距后让方框自然包裹；禁止先画死方框再塞内容。
- **滑块**：占满剩余宽度（`*` 列），`IsMoveToPointEnabled="True"` 点击轨道直接定位；按住箭头连续步进；行高 28 全部垂直居中保证水平中线对齐。
- **数值框**：58 宽、`Height=24`、**`MinHeight=0`（必须显式覆盖全局 TextBox 样式 MinHeight=30，否则实际高 30 超出行被裁剪，V51 修复）**、文字居中、默认 3 位宽度。
- **输入规则（仅整数）**：只允许数字（`Minimum<0` 时允许负号前缀），输入过程允许空/负号中间态，粘贴同样过滤；拒绝小数、科学计数法等。
- **提交钳制（回车/失焦/点击外部触发）**：解析失败沿用旧值；超出 `[Minimum, Maximum]` 自动钳制到最贴近值**并回显到输入框**（如输入 999、最大值 100 → 显示并生效 100；色调行输入 -999 → -100）。提交＝结束编辑，必须回显钳制值，防止残留原输入（V53 修复）。
- **上下箭头 = Windows NumericUpDown 标准调节按钮**（非自绘）：灰箭头 Path（`M 0,7 L 12,7 L 6,0 Z` / `M 0,0 L 12,0 L 6,7 Z`，10×6、`#646A73`）；按钮 18×13、白底 `#FBFBFC`、细边框 `#DCDFE6`、圆角 2、上下间距 2；RepeatButton 实现按住连续；**悬浮反馈与普通按钮一致（浅蓝底 `#F0F7FF` + 亮蓝边 `Color.PrimaryHover`，V52 确认）**，按下底 `#E8E9EB`。参考实例：GGStampWatermark 项目"不透明度/旋转"滑块行。

## 6. 弹窗规范

- 根：`WindowBg` + `Font.App` + `FontSize=12.5`；内容区 `Margin=16`；`SizeToContent=Height`、`ResizeMode=CanResize`（渲染参数窗）；简单确认窗可固定尺寸。
- 标题用 `SectionTitle`；说明用 `SectionHint`；底部提示 12.5px `Color.TextSecondary`。
- 按钮统一主界面按钮样式（Secondary/Primary/Danger/Square），宽度验证文字完整；按钮高度 30。
- **功能块用 Card 分块**（与主界面同风格：白底、`#C6CAD2` 边框、圆角 10），块内参数行间距 10，块间距 12。
- 参数滑块行：使用**拖动条控件**（见 §4.12，容器见 §4.11）——标题在上、滑块+数值框+箭头一行一体、方框适应内容（总高 30），数值框可手动输入。
- 方案按钮：宽 72、`Button.Secondary`、点击弹 ContextMenu（保存当前参数 / 加载方案参数；未保存时加载置灰）。
- 渲染参数弹窗分 3 块：**明暗与纹理**（印泥浓淡不均/渐变/径向压印）、**斑点**（内部斑点/斑点大小）、**颜色**（色调/局部露白）；参数行两列排布。

## 7. 交互文案与状态规范

- 未保存方案 → 菜单"加载"项 `IsEnabled=false`（灰字）。
- 参数全 0 = 干净原图（渲染参数）。
- 提示区文字：操作反馈在上、系统日志在下；时间戳仅日志使用。
- 控件初始状态（文字/勾选/可用性）在 XAML 声明，代码只做配置覆盖（见 §0.7）。

## 9. 外部规范引用与沟通方法（新 UI 元素的取用规则）

### 9.1 新 UI 元素必须"取"标准，禁止自由发挥
任何新控件/新交互元素，按以下顺序取样式：
1. **项目内已有实例优先**：先搜本规范 + Styles.xaml + 同系列项目（GGStampWatermark 等）中是否已有同类，有就复用/对齐（历史教训：箭头多次自绘均不达标，照 GGStampWatermark 现成滑块行一次到位）。
2. **Windows 标准控件取样式**：NumericUpDown（数字调节按钮）、ComboBox、ScrollBar、TextBox、CheckBox 等系统标准控件，按 WPF 默认模板视觉实现（尺寸、配色、间距对齐系统标准）。
3. **现代 UI 框架参考**：Windows 11 Fluent/WinUI（NumberBox 等）、Ant Design、Material Design 对应组件——只取结构/交互模式，配色字号仍套用本规范令牌。

### 9.2 用户描述新 UI 的有效方式（供用户参考）
按优先级：
1. **给清晰截图**（越大越好，含局部放大）。
2. **指认项目内已有实例**："像 GG 里不透明度旁边的箭头那样"——最准确，实现时直接读对应源码。
3. **指认标准组件名**："就是 NumericUpDown 的上下按钮 / ComboBox 的箭头 / ScrollBar 的滑块"。
4. **补充关键差异**：颜色、尺寸、间距、悬浮/按下状态与标准不同的地方。

### 9.3 实现方（AI）收到描述后的动作
1. 先按 9.1 顺序找标准/实例，不凭空画。
2. 找不到时，**明确说出"没有现成标准，我建议按 XX 实现"**并给出方案让用户确认，不擅自造样式。
3. 实现后把新控件登记到本规范对应章节（含参考来源）。
