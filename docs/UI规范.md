## 0. 使用总则（硬性）

1. **颜色一律用令牌**（`Color.*`），禁止在 XAML 中硬编码 `#RRGGBB`（极少数语义性 hover 深浅色除外，如 `#F0F0F0`/`#E0E0E0`，且须与本文件记录一致）。
2. **字体一律 `{StaticResource Font.App}`**，禁止硬编码字体名；窗口根元素统一 `FontFamily="Font.App"`。
3. **字号只允许下列档位（5 档）**：12.5（**默认**：正文、按钮、输入框、下拉、提示、日志）/ 13（SectionTitle 区块标题）/ 14（帮助窗口节标题）/ 18（帮助窗口大标题）/ 22（预览占位文字）。~~11 / 11.5 / 12~~ 已全部收敛到 12.5，禁止再出现。
4. **标题不要手写 `FontWeight="Bold"`**，用 `SectionTitle` 样式（13px 粗体）。
5. **按钮统一 `Button.Base` 派生**（Secondary/Primary/Danger/Square），圆角 6（方形入口除外）、MinHeight 30、Padding 12,5、Cursor Hand。
6. **下拉/菜单统一用全局 ComboBox / ContextMenu 样式**，禁止自绘覆盖控件；新增菜单项必须先查 MenuItem 模板（`ContentSource="Header"` 是必须项，禁用置灰绑定见 §4.4）。
7. **控件初始状态必须在 XAML 声明**：默认文字、默认勾选、默认可用性写进 XAML（如 `Content="盖章渲染"`、勾选框未选中时按钮 `IsEnabled="False"`），代码只负责按配置覆盖；禁止依赖某段代码初始化时才赋值（否则初始化路径未走到时控件为空/状态错，历史教训：盖章渲染按钮 `Content=""` 启动为空、未勾选时按钮未置灰）。
8. **新控件优先复用已有样式**：做新控件先搜索本文档与 Styles.xaml；确无同类才新增，且两处同步登记。
9. **交互状态记忆（展开/收起、上次使用值等）不属于设计规范**：由配置文件保存，新用户默认值按产品口径定（如按文字盖章默认收起），不写入本文档样式规则。

通用几何：圆角 6（方形入口 0）、`MinHeight=30`、`Padding=12,5`、`Cursor=Hand`。
**按压反馈（所有圆角/方形按钮统一）**：按下时内容下移 1px 产生按压感 + 整体 Opacity 0.9。实现：模板内 `Border.Padding` 从 0 变为 `0,1,0,0`（禁止用 RenderTransform 位移——WPF 模板内命名 Transform 的 Trigger 不可靠，历史教训）。
**宽度约定**：文字类按钮宽度 = 内容 + 左右 Padding（12×2）后留余量；固定宽按钮须验证文字完整显示（历史教训：56 宽"方案1"被裁，改 72）。

### 4.2 输入框 TextBox / PasswordBox
- 全局样式：白底、深灰边 1px、圆角 6、`Padding=8,2`、`Height=30`、内容垂直居中。
- **`Padding=8,2` 是硬性值（上下内边距 2px）**：12.5px 中文字体行高约 19px，30 高内内容区 = 30−4−2 = 24px，文字完整显示。曾用 `Padding=8,5` 导致内容区仅 18px、文字被裁剪一半（V46 修复）。
- **显式 `Height=30`，禁止仅 `MinHeight=30`**：MinHeight 会被内容撑破（内容 31px 时实际渲染 31px，比下拉框 30px 高 1px，用户目测不一致；V45 修复）。
- 聚焦：边框变主色蓝、加粗 1.5px。禁用：底 `#E8E8E8`、字 `#999999`。
- **禁止**在具体窗口覆盖模板或改背景。
- **高度统一 30（显式 `Height=30`）**：所有输入框、下拉框、密码框、预览工具栏按钮/页码框统一（含弹窗内输入框）。

### 4.3 下拉框 ComboBox
- 全局样式：白底、深灰边 1px、圆角 6、`MinHeight=30`、`MinWidth=80`。
- 悬停边框变蓝；下拉弹出层：白底、圆角 6、`MaxHeight=220` 滚动、`VerticalOffset=2`、淡入动画。
- 下拉项（ComboBoxItem）：圆角 4、`Margin=2,1`、`Padding=8,5`；hover/选中 = 浅蓝底 `#E6F0FF`；选中另加蓝字 + 字重 600。
- 可编辑模式（按文字盖章输入等）：隐藏选中项、显示内嵌文本框，样式与输入框一致。
- **宽度约定**：下拉框宽度与同排输入框对齐；内容放不下时加宽而不是截断（历史教训）。
- **印章文件 / 当前文件下拉框显式 `Height=30`**，与输入框绝对一致；**禁止 `MaxHeight`**（只限上限、不保最小，内容少时框会缩矮，历史教训）；可编辑模式下内嵌文本框样式与输入框一致。

### 4.4 菜单 ContextMenu / MenuItem（方案按钮、右键菜单等）
- ContextMenu：白底、深灰边 1px、圆角 6、`Padding=4`。
- MenuItem：圆角 4、`Margin=2,1`、`Padding=8,5`、字号 12.5；hover = 浅蓝底；禁用 = 灰字（`Color.TextHint`）。
- **模板必须 `ContentSource="Header"`**（漏写会导致菜单项空白、菜单缩成极小，历史教训）。
- **禁用置灰 = 模板触发器直接设置（禁止 Foreground 绑定）**：`ContentPresenter` 上**不要写任何 Foreground 本地值/绑定**——正常态文字继承 `MenuItem.Foreground`（黑）；禁用态用 `ControlTemplate.Triggers` 里 `IsEnabled=False` 触发器 `Setter TargetName="content" Property="TextElement.Foreground"` 置灰（`Color.TextHint`）。
  **根因（V54 实测确认）**：`TextElement.Foreground="{Binding ...}"` 是本地值，优先级高于模板触发器，导致禁用置灰不生效（历史反复：加载方案置灰 3 次不生效）；`TemplateBinding` 也不支持附加属性（静默失效）。两种写法均禁止。
- 菜单项"未保存→加载置灰"等状态用 `IsEnabled` 控制，禁止手工改文字颜色。

### 4.5 勾选 CheckBox（方形勾选规范，V115 更新）
- **方形勾选框：圆角方框 `CornerRadius=3`**（编号 check-square 4 号风格；非直角、非圆形——**图标风格统一为圆角方框，禁止圆形框**，见 §11 图标资产清单）；方框 16×16、白底。
- 未选中：灰边 `#C6CAD2`（同款方框去勾）；**选中：蓝底 `#1677FF` + 白勾**（勾形用 `Icon.Check`=共享图标库 check-square 4 号勾，填充型白勾，9×7 居中）；hover：边框亮蓝 `#4096FF`；**禁用：对模板根容器（方框+文字）整体 `Opacity=0.45`（V80 定稿）**。
  **禁用置灰的实现禁令（V78~V79 教训）**：勾选框文字由 ContentPresenter 内部创建的 TextBlock 呈现，命中全局隐式 `TextBlock` 样式（`Foreground=Color.Text`，Style setter 优先级高于属性继承）——模板内设置 `Foreground`（无 TargetName，作用 TemplatedParent，继承不走逻辑树）和 `TargetName="content" + TextElement.Foreground`（继承值压不过 Style setter）**均不生效**。禁用态只允许整体 Opacity 淡化，禁止试图单独把文字置灰。
- 字号 12.5、`Cursor=Hand`、内容垂直居中、文字与方框间距 8。
- **方形入口组合**（盖章渲染）：方形勾选框 + `Button.SecondarySquare` 方形按钮；未勾选时按钮整体置灰（IsEnabled=false）不可点，勾选后变亮可点、点击弹设置窗。
- RadioButton 沿用系统模板，仅字号 12.5。

### 4.13 多控件区域表格组对齐（N 行 M 列自适应 Grid，硬性）
- **用途**：印章参数区、其他设置区等"多行多列、每格多个控件"的区域。**禁止逐列像素微调对齐**（历史教训：V59~V64 连续 6 版靠 Margin 微调仍对不齐；V65 表格化一次到位）。
- **结构**：`Grid` 行/列全部 `Auto`；**每个单元格放一个横向 `StackPanel` 逻辑组**；**同功能区的多行共用一个 Grid，跨功能区拆独立 Grid（各自表格）**。
- **组内组合（组 = 单元格内唯一横向容器）**：
  - `标题 + 输入框 + 单位`：标题↔输入框 6px、输入框↔单位 6px；
  - `勾选框 + 按钮`：间距 2px。
- **单元格内**：`HorizontalAlignment="Left"`、`VerticalAlignment="Center"`（垂直居中 + 左对齐）。
- **列宽**：由该列**最宽组** Auto 撑开（含组自身 Margin）；**列间距 24、行间距 10**。
- **组内控件宽度统一**：TextBox 统一 `Width=46, Height=30, TextAlignment=Center`；下拉/按钮按内容定宽（文字必须完整显示，禁止截断）。
- **总宽不足**：加宽所在容器/窗口，禁止压缩控件。
- **列数**：**不设硬性上限**，由内容与设计决定（当前实际均为 3 列，未来可扩展 4 列甚至更多）；仅当某行内容超出该行可容纳列数时才换行到下一行（保持该表格既定列数）。
- **适用实例（印章参数区 = 3 个独立表格，V71 重构）**：
  - 表格1 印章显示参数：行1 印章尺寸 / 旋转 / 旋转处理；行2 不透明度 / 随机角度位移 / 盖章渲染
  - 表格2 骑缝章：骑缝位置 / 位置 / 分割数
  - 表格3 容差：去除图章白色背景 / 容差 /（空）
- **适用实例（按文字盖章区 = 2 个功能区 + 操作行，V75~V76 重构）**：
  - 功能区1 搜索与放置（2 列表格）：列1 `3*` 关键词输入框填满 / 列2 `1*` 中心偏移（勾选+方形按钮，组左对齐、垂直居中）；比例判定：列宽按内容实算（内容宽约 580px 时 1/4 ≈145px > 组宽≈108px → 用 3:1；放不下则降 2:1）
  - 功能区2 附近关键词过滤：勾选行（附近关键词+说明）→ 整行关键词输入框 → 3 列表格（上下文范围[10]字 / 排除空格 / 匹配[末列 `*` 填满]）；未勾选时块内标题+控件全部置灰（`TextBlock.AutoContextLabel`，§7.1）
  - 操作行：按文字放置印章 / 撤销放置（主操作，**不随过滤勾选置灰**）
  - 功能区之间用分隔线（1px + 间距 20）区隔：搜索与放置 ／ 附近关键词过滤 ／ 操作按钮
- **其他区域同类多控件对齐一律照此执行**；组内某格有勾选框时，勾选框左缘 = 组左缘 = 列起点（CheckBox 模板方框无 Margin，天然对齐）。
- **功能分区 = 独立表格（V68/V71 规范，硬性）**：不同功能区（如"其他设置"的数字签名区与 PDF 密码区；印章参数区的 3 个功能区）是**各自的独立 Grid**，列宽自主。**禁止把不同功能的行放进同一个 Grid 共享列定义**——改其中一个功能的列宽会连带压缩另一个功能（固定 200px 密码框被 1/3 等宽列裁剪导致"第二行被遮挡"，V68）；**禁止用 ColumnSpan 补救**。表格之间用**分隔线**（1px、`Color.Border`、横贯内容区）区隔，间距 20（如 Margin `0,9,0,10` 含线 1px）；**禁止套内嵌卡片**（主界面已是 Card 风格，框套框三层嵌套）。V66 曾用"同一表格内插分隔线行"过渡，V71 起废弃，统一改拆表格。
- **跨表格列宽联动（SharedSizeGroup，V71 验证）**：同一 Card 内多个表格**列数相同**（同为 N 列）且需要上下对齐时：父容器设 `Grid.IsSharedSizeScope="True"`，各表格同名列声明**同名 `SharedSizeGroup`**（列宽必须 `Auto`）——框架自动取各表格该列**最宽组**作为共享列宽，列对齐与单表格时完全一致，仍由内容决定、无需写死像素。实例：印章参数区 3 个表格的列分别用 `SharedSizeGroup="SPCol0/SPCol1/SPCol2"`。
- **列数不同的表格（各自独立，不共享列宽）**：同一 Card 内列数不同的表格（如"其他设置"：表格1 三列 / 表格2 两列）各自独立 Grid、列宽自主，**不做列共享**（列结构不同无法共享）；仅保证各表格总宽度统一撑满同一内容区。
- **列宽策略（Auto 列陷阱，V67 教训）**：Auto 列宽由"列内控件的实际布局宽度"决定——列内控件**禁止设置超出内容需求的固定 Width**（如内容仅需约 73px 的下拉框被硬设 90px，列就多出虚宽），否则列宽 ≠ 内容实际宽度，列间出现多余空白、列与列宽度不匹配。Auto 列要么让内容自然撑开，要么该列改自适应（`*`）。
- **末列控件尾部对齐（V76~V77 验证，硬性）**：表格**末列**（其后不再有其他列）若内含固定宽控件（如下拉框），该列用 `*`、控件 `HorizontalAlignment="Stretch"` + `MinWidth="0"`，使控件右缘对齐该行尾部/卡片右缘，视觉整齐；禁止末列留 `Auto` 造成行尾悬空空白（历史：按文字盖章区"匹配"下拉右缘未对齐到行尾）。
- **组内"填满"必须用 Grid，禁止横向 StackPanel 拉伸（V77 教训，硬性）**：`StackPanel Orientation="Horizontal"` 沿排列方向**不拉伸子元素**（测量给无限宽、子元素取 DesiredSize），`HorizontalAlignment="Stretch"` 会被忽略——"标题 + 控件填满剩余"的组必须用 **Grid 2 列（标题 `Auto` + 控件 `*`）**，如盖章方式区 2×2、按文字盖章区"匹配"下拉（V76 用 StackPanel+Stretch 修复失败，V77 改 Grid 生效）。
- **标题分散对齐（V73 验证）**：表格内上下行标题**字数不同**（如 3 字"骑缝章"在 4 字"页面盖章"下方、3 字"分割数"在 4 字"旋转处理"下方）时，少字标题**分散对齐**到多字标题的宽度（标题占位一致），使标题后的控件（下拉/输入框）**左缘上下对齐**。实现：**N 等分 Grid 真分散**——少字标题拆成每字一个 TextBlock、各占 `*` 列、`TextAlignment="Center"`（如 3 字标题 = 3 列等分 Grid）；宽度基准 = 12.5px 字号中文字符 ≈13.25px/字，4 字宽 = `Width="53"`（注释注明基准）。**禁用** letter-spacing 类假分散（WPF 无分散属性，单行 Justify 不生效）。

### 4.16 左栏空间分配（日志区最小高度与压缩方向，V111 定稿）
- 左栏外框 `leftFrame`：**方角（CornerRadius=0）、贴窗口顶（Margin=0,0,0,0）**，底部到窗口底；不再用圆角大外框（V104 用户确认方角提升）。
- leftGrid 四行：Row0 设置区（`*`）/ Row1 盖章按钮+输出 DPI 行（Auto）/ Row2 分隔线（1px）/ Row3 日志区（`*`，**MinHeight=300**）。
- **可用空间 = 真实客户区（硬性）**：`space = rootGrid.ActualHeight - 外框边框 - 固定行高`。**禁止用 leftGrid.ActualHeight 计算**——它被自身 Pixel 行总和撑住，窗口变矮时保持旧值 → space 不变 → 行高永不更新（死锁，V109~V111 根因）；rootGrid 撑满客户区不受行高反向影响。
- **分配口径**：
  - `ideal` = 设置区理想高度（"3 展开、4/5 收起"组合下内容高度，`EnsureSettingsIdealHeight` 静默测量）；
  - `space ≥ ideal + 300` → 设置区=ideal（封顶），日志区=剩余；
  - `space < ideal + 300` → 日志区=300（保底），压缩全部落设置区（设置区有滚动条，不怕压）；
  - 极端 `space < 300` → 设置区=0、日志区=space。
- **压缩方向（用户锁定口径）**：日志区高于 300 时优先压缩日志区；到达 300 后压缩全部落设置区；窗口拉高**先恢复设置区到 ideal，再增长日志区**。
- 更新时机：窗口 SizeChanged（Dispatcher.Loaded 优先级，避免布局未完成读取旧值）+ 折叠状态变化后。

### 4.17 输出文件名格式自定义（V132，其他设置卡片内功能分区）
- **用途**：其他设置卡片内第三功能分区（表格3），让用户自定义输出文件名格式；替代旧版写死的"已盖章V{n}"规则。
- **结构（自上而下）**：小节标题"输出文件名格式自定义"（普通正文 13px，无序号）→ **2×2 表格**（行1：位置/命名文字；行2：递增类型/位数；两列等宽 `*`，单元格内"标题 Auto + 控件 `*` 撑满"，行距 10）→ **时间戳行**（占半行，同 PDF 密码行样式：勾选框 + 格式下拉 Width=200 左对齐）→ **效果预览灰字行**（12px、`Color.TextSecondary`、Wrap，实时显示两次盖章的文件名：`▸ 效果预览：xx_已盖章V1.pdf　再盖一次 → xx_已盖章V2.pdf`）。
- **控件顺序 = 文件名实际组成顺序**：先位置（文件名后/前）→ 命名文字 → 递增类型 → 位数 → 时间戳。
- **递增编号规范（业界批量重命名标准，Renamio/BRU）**：递增**必选（无"无"选项）**，由两个维度组成——①**类型**：数字 1、2、3 / 大写字母 A、B、C / 小写字母 a、b、c；②**位数**：1 位 / 2 位补零 01 / 3 位补零 001（仅数字生效，字母忽略）。字母 26 个后自动进位（A…Z→AA、AB），编号按目标目录已有文件取最大 +1 防覆盖。
- **时间戳**：勾选后格式下拉可选；4 种安全格式（`20260911` / `2026-09-11` / `20260911-2030` / `2026-09-11-20-30`，仅数字与连字符，不含文件名非法字符）；取**生成文件时刻**的本地时间；位置固定插在**命名文字之后、编号之前**；时间戳存在时时间戳与编号之间自动加 `_` 分隔避免数字粘连（`已盖章V20260911_1`）。
- **命名组成规则**：默认位置=后 → `源文件名_mark[ts][_编号].pdf`；位置=前 → `mark[ts][_编号]_源文件名.pdf`；命名文字允许为空（空则只有时间戳+编号：`xx_20260911_1.pdf`）。
- **旧标记剥离与防覆盖**：源文件名已带当前规则产出的旧标记段（数字/字母编号、带或不带时间戳）时自动剥离再编号，避免 `xx_已盖章V1_已盖章V1`；输出与源文件同路径时视为已存在自动 +1。
- **配置与迁移**：config.ini 新增 `outputNameInit/ outputNameMark / outputNamePos / outputNameSeqType / outputNamePad / outputNameTs / outputNameTsFormat`；`outputNameInit` 标志不存在时做一次旧 `fixStr/fixType` 迁移（旧标记文字 + "V"、位置取 fixType），迁移后写 `outputNameInit=1`，用户清空命名文字不再触发迁移。控件变化即保存（启动赋值阶段 `IsLoaded=false` 不保存）。
- **代码位置**：`Library\OutputFileNamingPolicy.cs` 新版 `GetNextFileName/GetNextOutputPath(OutputNamingOptions)`（旧 string 重载保留兼容）；MainWindow 两处调用（目录/文件模式）统一用 `BuildOutputNamingOptions()`。

## 7. 交互文案与状态规范

### 7.1 控件置灰规范（IsEnabled 与数据状态绑定，硬性）
- **置灰的本质**：`IsEnabled=false`。置灰不是视觉装饰，而是"该操作当前不可用"的状态表达。
- **第一原则：置灰必须与数据/业务状态挂钩**，由状态驱动、随状态更新，禁止与状态脱钩：
  - 勾选状态（如盖章渲染）→ 未勾选时"设置参数"按钮置灰；
  - 存储状态（如渲染方案）→ 未保存方案时菜单"加载方案参数"置灰；
  - 加载状态（如源文件/印章）→ 未加载时相关操作置灰；
  - 输入状态（如未勾选随机时，角度/位移输入框置灰不可填）。
- **实现方式（按场景二选一）**：
  1. **XAML 静态声明**：初始状态写进 XAML（`IsEnabled="False"`，§0.7），运行时按配置/数据覆盖。
  2. **动态创建**（代码 new 控件，如方案菜单）：创建时按数据状态直接设置 `IsEnabled`；**文字类控件（MenuItem 等）的 Header 直接用 TextBlock 并显式设置 `Foreground`**（有数据=`Color.Text`，无数据=`Color.TextHint`）——TextBlock 本地值绝对生效（V56 实测确认）。
     **不要用** `MenuItem.Foreground`（Control 属性传不到内部文字）、`TextElement.SetForeground`（动态菜单继承链不可靠，V55 实测失败）、模板触发器（本地值优先级问题，V54 失败）——三条路全部踩过。
- **禁止**：
  - 禁止用模板触发器（ControlTemplate.Triggers 的 `IsEnabled=False → 改文字颜色`）实现动态控件的置灰——本地值/继承链不可靠，历史反复 4 次不生效（加载方案置灰 V38~V54）；
  - 禁止手工硬编码颜色绕过 `IsEnabled`（菜单禁用文字颜色 = `Color.TextHint`，见 §4.4）；
  - 禁止只用 `IsEnabled` 不管文字颜色（禁用项文字必须灰色可辨）。
- **从属标题文字灰显（V76，硬性）**：功能块未启用时（如未勾选"附近关键词"），块内**标题文字也要变灰**，不能只灰输入控件。TextBlock 本身不响应 `IsEnabled` 视觉变化，必须用样式触发器：`TextBlock.AutoContextLabel`（`IsEnabled=False` → `Foreground=Color.TextHint`）；联动方法（如 `UpdateContextFilterEnabled`）里把标题与控件一起设 `IsEnabled`。勾选框自带文字随 CheckBox 禁用自动灰，无需处理。
  **IsEnabled 方向（V113 教训，硬性）**：AutoContextLabel 的灰色由 `IsEnabled=False` 触发，联动方法里 **`IsEnabled` 必须与状态同向**（状态=true → `IsEnabled=true` 黑字；状态=false → `IsEnabled=false` 触发灰）。禁止写 `= !状态`（历史三处写反：主界面容差、子印章整行标题、子印章容差——子印章 V128 已删除，示例保留供参考）。
- **勾选框文字单独置灰（V113，硬性）**：需要"勾选框本身可点、但文字随勾选状态置灰"时（如"去除图章白色背景"未勾选时整行弱化），**禁止设置 `CheckBox.Foreground`**（Content 内 TextBlock 命中全局隐式 TextBlock 样式，Style Setter 优先级高于继承值，无效）；必须把 Content 改为显式 `TextBlock`（`Style="{StaticResource TextBlock.AutoContextLabel}"` + `x:Name`），代码用 `TextBlock.IsEnabled` 控制（同 AutoContextLabel 方向规则）。
- **模板控件的禁用态统一"整体 Opacity 0.45"（V80~V81 定稿，硬性）**：勾选框（§4.5）、下拉框（§4.3）等自定义模板控件的禁用态，**一律对模板根容器（方框/底色+文字一起）设 `Opacity=0.45`**。
  **实现禁令（V78~V81 教训）**：控件自带文字（ContentPresenter 呈现的 Content/SelectionBoxItem）由内部 TextBlock 呈现，命中全局隐式 `TextBlock` 样式（`Foreground=Color.Text`，Style setter 优先级高于属性继承）——模板内设 `Foreground`（无 TargetName，作用 TemplatedParent，继承不走逻辑树）或 `TargetName + TextElement.Foreground`（继承值压不过 Style setter）**均不生效**；曾对勾选框改 3 次、下拉框 1 次失败。禁用态只允许整体 Opacity 淡化，禁止试图单独把控件文字置灰。
- 状态源变化时（如勾选、保存方案、加载文件），必须同步刷新相关控件 `IsEnabled`（用同一更新方法集中刷新，如 `UpdateTextureEnabled()`）。

### 7.2 其他状态与文案
- 参数全 0 = 干净原图（渲染参数）。
- 提示区文字：操作反馈在上、系统日志在下；时间戳仅日志使用。
- 控件初始状态（文字/勾选/可用性）在 XAML 声明，代码只做配置覆盖（见 §0.7）。
- 交互状态记忆（折叠展开、上次输入等）由配置保存，新用户默认值见产品口径，不属于设计规范（见 §0.9）。

### 7.3 方案加载状态反馈（选中态 + 当前参数提示，硬性）
- **原则**：加载了某套方案后，界面必须持续给出"当前用的是方案N"的反馈，不能只看参数数字。
- **三重反馈（组合使用）**：
  1. **方案按钮选中态**：对应方案按钮切换为 `Button.PresetSelected`（浅蓝底 + 蓝边框加粗 + 深蓝加粗字，视觉同视图切换选中态 §4.9），其余方案恢复 `Button.Secondary`；恢复默认后全部普通。
  2. **"当前参数"小灰字**：方案按钮下方一行 `SectionHint` 样式小灰字，显示"当前参数：方案N / 自定义"。
  3. **操作反馈**：加载时提示区写"已加载方案N参数"（`SetOperationHint`）。
- **状态流转（与数据绑定，见 §7.1）**：
  - 加载方案N → 选中方案N + 小灰字"方案N" + 操作反馈；
  - 手动修改任一参数 → 清除选中（回到自定义），小灰字"自定义"（加载赋值用 `_loadingPreset` 标志区分，避免误清除）；
  - 恢复默认（全 0）→ 清除选中。
- **随章记忆**：方案号与渲染参数一起存入印章参数节（`texturePresetIndex`，0=自定义/1-4=方案N），切章/重开软件后选中态与参数保持一致。

## 9. 外部规范引用与沟通方法（新 UI 元素的取用规则）

### 9.1 新 UI 元素必须"取"标准，禁止自由发挥
任何新控件/新交互元素，按以下顺序取样式：
1. **项目内已有实例优先**：先搜本规范 + Styles.xaml + 同系列项目（GGStampWatermark 等）中是否已有同类，有就复用/对齐（历史教训：箭头多次自绘均不达标，照 GGStampWatermark 现成滑块行一次到位）。
2. **Windows 标准控件取样式**：NumericUpDown（数字调节按钮）、ComboBox、ScrollBar、TextBox、CheckBox 等系统标准控件，按 WPF 默认模板视觉实现（尺寸、配色、间距对齐系统标准）。
3. **现代 UI 框架参考**：Windows 11 Fluent/WinUI（NumberBox 等）、Ant Design、Material Design 对应组件——只取结构/交互模式，配色字号仍套用本规范令牌。

### 9.2 用户描述新 UI 的有效方式（供用户参考）
按优先级：
1. **给清晰截图**（越大越好，含局部放大）。
2. **指认项目内已有实例**："像 GG 里不透明度旁边的箭头那样"——最准确，实现时直接读对应源码。
3. **指认标准组件名**："就是 NumericUpDown 的上下按钮 / ComboBox 的箭头 / ScrollBar 的滑块"。
4. **补充关键差异**：颜色、尺寸、间距、悬浮/按下状态与标准不同的地方。

### 9.3 实现方（AI）收到描述后的动作
1. 先按 9.1 顺序找标准/实例，不凭空画。
2. 找不到时，**明确说出"没有现成标准，我建议按 XX 实现"**并给出方案让用户确认，不擅自造样式。
3. 实现后把新控件登记到本规范对应章节（含参考来源）。

## 10. 布局回归测试（/layouttest，V112 起，硬性）

- **目的**：任何布局/高度分配改动后自动验证，防止"改好 A 弄坏 B"回归（历史：日志区布局反复出问题，靠人工逐版验证效率极低）。
- **启动方式**：命令行参数 `/layouttest`（不传则完全不影响正常使用）。
- **执行内容**：主窗口自动按预设窗口高度序列 **680 / 850 / 1030 / 1200 / 1500** 遍历，每次布局完成后断言：
  1. **日志区高度 ≥ 300**（最小高度保底）；
  2. **行高总和 ≤ 窗口客户区**（设置区+固定行+日志区不溢出）；
  3. **最低高度（≤700）下日志区恰为 300**（压缩方向正确）；
  4. **高窗口（≥1400）下设置区封顶到理想高度**（`_settingsIdealHeight`）。
- **结果**：写运行目录 `layout_test.log`（逐行 PASS/FAIL + 数值 + 汇总）；测试结束**恢复原窗口尺寸后自动退出**（不污染用户配置）。
- **验证流程（硬性）**：布局/高度分配改动 → 编译 → 跑 `/layouttest` → 确认全 PASS → 再交付用户测试。
- 实现位置：`MainWindow` 构造函数检测参数 → `RunLayoutTest()` + `WaitForLayout()`（Background 优先级等待，确保 Loaded 优先级的 UpdateSettingsHeight 已执行）。
